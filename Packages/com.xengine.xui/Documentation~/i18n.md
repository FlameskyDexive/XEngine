# Translation

The source string is the key. `<Text id="XTxtTitle">Sign in</Text>` is looked up as `"Sign in"`, and a
missing entry resolves to `"Sign in"`.

That one decision is what makes the rest of this optional. A project that never runs the extractor
displays correctly. A locale that is 40% translated shows 40% translated and 60% English rather than
60% `MENU_TITLE_1`. The catalog is an overlay on a screen that already works, not a prerequisite for it
working at all.

## What is translatable

Inline text on the tags that display it, and `placeholder` / `text` on `InputField`. Nothing else.

```xml
<Text id="XTxtTitle">Sign in</Text>                       <!-- extracted -->
<Btn  id="XBtnGo">Start</Btn>                             <!-- extracted -->
<InputField id="XInputAccount" placeholder="Account"/>    <!-- extracted -->
<Image id="XImgLogo" sprite="UI/logo.png" color="accent"/> <!-- not prose -->
```

Widening the rule to "any attribute that looks like prose" is how ids, sprite paths, and theme tokens
end up in a translator's queue.

`translate="false"` opts out, and is **inherited**:

```xml
<VStack id="XVsStats" translate="false">
  <Text id="XTxtFps">FPS</Text>
  <Text id="XTxtDraws">Draw calls</Text>
  <Text id="XTxtHelp" translate="true">Press F1 for help</Text>   <!-- back in -->
</VStack>
```

One decision covers a panel, and a child can opt back in for the one label that really is prose.

## From C#

```csharp
Xui.Tr("Saved")
Xui.Tr("Post", context: "verb")      // when one source string needs two translations
```

The argument must be a **literal**. `Xui.Tr($"Level {n}")` cannot be extracted at all — nothing static
exists to put in a catalog — so translate first and format after:
`string.Format(Xui.Tr("Level {0}"), n)`.

## Extraction

```bash
xengine-cli xui-i18n-extract --project <root> --locales zh-Hans,ja --out UI/Locales
```

Documents are extracted **after template expansion**: a template body holds `placeholder="{hint}"`,
which is not a string anyone reads, while the `hint="Account"` at the usage site is. Extracting the
unexpanded tree would silently miss every string passed into a template — the ones most likely to be
shared, and so the ones a translator most needs.

The result is one `.po` per locale, in the gettext format Poedit, Weblate, and Crowdin already read.

**The merge never destroys work.** Running the extractor again:

| Situation | What happens |
|---|---|
| A string with a translation is still there | Kept, references rewritten |
| A new string appears | Appended, untranslated |
| No source mentions a string any more | Marked obsolete (`#~`), **translation kept** |
| An obsolete string comes back | Revived with its translation |

That is why obsolete entries are kept rather than deleted: a rename, a reverted commit, or a
temporarily commented-out screen must not cost a translation someone was paid for. Re-running over
unchanged sources produces a byte-identical file, so it is safe on every build.

Plural forms are **not** supported. `msgid_plural` is rejected with an error rather than half-read —
silently keeping the singular would be a wrong translation in every language with plural rules, and
nothing downstream would ever report it.

## At runtime

```csharp
Xui.Locale = "zh-Hans";
Xui.LocaleChanged += locale => RefreshFormattedLabels();
```

Switching **re-translates open screens in place** rather than rebuilding them. Scroll position, input
focus, and anything a controller wrote into a label after the build all survive. The corollary is worth
stating: a label your code set is not clobbered by a language switch, and is also not re-translated —
that is what `LocaleChanged` is for.

Catalogs are `.po` assets; the importer registers each one as it imports, so saving a translation shows
up on screen immediately. In the editor, `runtime_xui_locale` loads every catalog in the project and
switches, reporting how many strings were actually written back into open screens.

## Fonts

A font named after the locale, beside its catalog, becomes that locale's font:

```
Assets/UI/Locales/zh-Hans.po
Assets/UI/Locales/zh-Hans.ttf     ← bound to zh-Hans automatically
```

From code: `Xui.RegisterLocaleFont("zh-Hans", font)`.

This is **whole-asset substitution, not per-glyph fallback**. XGUI's text has Bold / Italic / Mono slots
but no fallback chain by character range, so a locale whose glyphs the default font lacks needs a font
of its own. Saying so plainly beats implying a fallback that does not exist — the failure would
otherwise surface only in the locale nobody on the team reads.

## Known limitation

**CJK text currently renders blank**, engine-side. With a Chinese font assigned and the string set,
both are correct in memory — `Text.Text` reads back `登录`, the font resolves to `FamilyName=simhei` —
and nothing draws; the same font with English strings renders normally, so font substitution works and
glyph rasterization is the gap. Evidence is in `docs/superpowers/evidence/xui/m10-i18n-*.png`.

Until that is fixed, verify a translation by reading the text back (`runtime_eval`,
`runtime_xui_locale`'s `retranslated` count), not by looking at a screenshot.
